    From a script or agent

    A script or agent on your machine can send the same report straight to the report service. There is no account or key.

    Send POST https://bug-reports.kakudio.workers.dev/api/reports with a JSON body of four fields:

    mod_id
    the mod's id from the list above
    description
    what went wrong, in your words
    log_name
    the run log's file name, without its folder
    log
    the whole run log, as text

    For example, for a Shell Game run:

    curl https://bug-reports.kakudio.workers.dev/api/reports \
  -H 'Content-Type: application/json' \
  -d '{
    "mod_id": "shell-game",
    "description": "Sparrow never showed up, so I could not reach the Ankh.",
    "log_name": "20261002-140316-ShellGame-randomizer-126973-run-8288215085007426999,338101898040651254-2.txt",
    "log": "Shell Game run report\nRandomizer seed: 126973\n…"
  }'

    Put the whole file in log, not just its start. It goes in as a JSON string, so its line breaks, quotes and backslashes need escaping; any JSON library does that for you.

    A report that is taken gets 201 and its reference:

    {"reference":"ABCD-1234"}

    Anything else gets an error status and a message written for you, to show as it is:

    {"error":"This run log is too large to send (the limit is 1 MB)."}

    Instructions for an agent

    To have an agent on your machine send a report for you, give it these instructions exactly as shown, along with what went wrong.

    Send a bug report for a Kakudio mod on my behalf.

1. Find the run logs. Each covered mod writes one plain-text run log per run
   into its own folder in my Spelunky 2 game folder. On Steam that is usually
   C:\Program Files (x86)\Steam\steamapps\common\Spelunky 2
   If Spelunky 2 is in another Steam library, look there. If you can't find
   the folder, ask me for its path.

   Covered mods:

   Shell Game
     mod_id:      shell-game
     folder:      Mods\Data\ShellGame\run_reports
     file names:  *-ShellGame-randomizer-*-run-*-*.txt
     first line:  Shell Game run report

2. Pick the newest run log: the file in the mod's folder whose name matches
   its file-name pattern (case doesn't matter) and that was modified last,
   unless I name another run. Its first line must be exactly the mod's first
   line. If it isn't, tell me and don't send it.

3. Send it:
   POST https://bug-reports.kakudio.workers.dev/api/reports
   Content-Type: application/json
   with a JSON body of four fields:
     mod_id       the mod's id from the list above
     description  what went wrong, in my words; ask me if I haven't said
     log_name     the run log's file name, without its folder
     log          the whole run log, as text, not just its start
   Build the body with a JSON library so the log's line breaks, quotes and
   backslashes are escaped.

4. Tell me the answer:
   201: the body is {"reference":"ABCD-1234"}. Tell me the report was sent
     and give me the reference, and tell me to keep it.
   Any other status: the body is {"error":"..."}. Show me the error message
     exactly as it is, and don't send again unless I ask.

    When a report is refused

    The service turns a report away when:

    • the run log's file name doesn't match its mod's run logs (case doesn't matter);
    • the run log isn't UTF-8 plain text;
    • its first line isn't its mod's run-log header, for Shell Game Shell Game run report;
    • the description is empty or over 20,000 characters;
    • the run log is empty or over 1 MB;
    • the mod isn't on the list;
    • one sender has tried more than 5 reports in a minute, sent or not;
    • the service is full for the day, or full overall.

    The message says which. Pick another run or shorten the description and send again, or, if the service is busy or full, try again later.

    Keep your reference

    Every report that gets through has a reference, eight letters and digits such as ABCD-1234, shown when you send it or returned by the service. Keep it: it is how your report is found again when you talk about the bug.
