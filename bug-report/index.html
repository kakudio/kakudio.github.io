    A bug report for a Kakudio mod is the run log of the run that went wrong and a description of what happened, sent to the Kakudio report service in one request. A script or agent can send it without the form. There is no account or key.

    1. Find the run logs

    Every run of a covered mod writes a run log, a plain text file, into the mod's own folder inside the Spelunky 2 game folder. On Steam the game folder is usually C:\Program Files (x86)\Steam\steamapps\common\Spelunky 2. If Spelunky 2 is in another Steam library, it is there instead: in Steam, right-click Spelunky 2 and choose Manage → Browse local files. If it can't be found, ask the player for its path.

    Covered mods:

    • Shell Game: mod_id shell-game; folder Mods\Data\ShellGame\run_reports; file names *-ShellGame-randomizer-*-run-*-*.txt; first line Shell Game run report

    2. Pick the newest run log

    In the mod's folder, take the file whose name matches the mod's pattern (case doesn't matter) and that was modified last, unless the player names another run. Its first line must be exactly the mod's first line; if it isn't, the service won't take it, so tell the player and don't send it.

    3. Send it

    Send POST https://bug-reports.kakudio.workers.dev/api/reports with Content-Type: application/json and a JSON body of four fields:

    • mod_id: the mod's mod_id from step 1;
    • description: what went wrong, in the player's words (ask them if they haven't said);
    • log_name: the run log's file name, without its folder;
    • log: the whole run log, as text, not just its start.

    The log goes in as a JSON string, so its line breaks, quotes and backslashes need escaping; build the body with a JSON library and it does that for you. For example, for a Shell Game run:

    curl https://bug-reports.kakudio.workers.dev/api/reports \
  -H 'Content-Type: application/json' \
  -d '{
    "mod_id": "shell-game",
    "description": "Sparrow never showed up, so I could not reach the Ankh.",
    "log_name": "20261002-140316-ShellGame-randomizer-126973-run-8288215085007426999,338101898040651254-2.txt",
    "log": "Shell Game run report\nRandomizer seed: 126973\n…"
  }'

    4. Read the answer

    A report that is taken gets 201 and its reference. The report is sent; give the player the reference and tell them to keep it.

    {"reference":"ABCD-1234"}

    Any other status means the report wasn't sent, and comes with a message written for the player. Show it to them exactly as it is, and don't send again unless they ask.

    {"error":"This run log is too large to send (the limit is 1 MB)."}

    When a report is refused

    The service turns a report away when:

    • the run log's file name doesn't match its mod's run logs (case doesn't matter);
    • the run log isn't UTF-8 plain text;
    • its first line isn't its mod's run-log header, for Shell Game Shell Game run report;
    • the description is empty or over 20,000 characters;
    • the run log is empty or over 1 MB;
    • the mod isn't one of the covered mods;
    • one sender has tried more than 5 reports in a minute, sent or not;
    • the service is full for the day, or full overall.

    The message says which. Pick another run or shorten the description and send again, or, if the service is busy or full, try again later.

    Keep your reference

    Every report that gets through has a reference, eight letters and digits such as ABCD-1234, shown when you send it or returned by the service. Keep it: it is how your report is found again when you talk about the bug.
