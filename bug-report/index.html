With the bug reporter

The Kakudio bug reporter is a Windows app that finds your recent runs and sends the one you pick. It is a single program: no installer, no account.

Download the bug reporter

The first time you run it, Windows SmartScreen asks whether to run an unrecognized app. Choose More info → Run anyway.

  1. Run it. It finds your Spelunky 2 folder on its own; if it can't, it asks once and remembers.
  2. Pick the run that went wrong. Runs are listed newest first.
  3. Describe what went wrong: what you were doing, what you expected and what happened instead.
  4. Send the report.
  5. Keep the reference it shows, such as ABCD-1234.

If the report can't be sent, the app says why and keeps your description so you can try again.

Mods it covers

Every run of a covered mod writes a run log, a plain text file, into the mod's own folder under Mods/Data/ in your Spelunky 2 game folder. On Steam that is usually C:\Program Files (x86)\Steam\steamapps\common\Spelunky 2. The newest file is your most recent run.

Without the app

You, or a script or agent on your machine, can send the same report straight to the report service. There is no account or key.

Send POST https://bug-reports.kakudio.workers.dev/api/reports with a JSON body of four fields:

mod_id
the mod's id from the list above
description
what went wrong, in your words
log_name
the run log's file name, without its folder
log
the whole run log, as text

For example, for a Shell Game run:

curl https://bug-reports.kakudio.workers.dev/api/reports \
  -H 'Content-Type: application/json' \
  -d '{
    "mod_id": "shell-game",
    "description": "Sparrow never showed up, so I could not reach the Ankh.",
    "log_name": "20261002-140316-ShellGame-randomizer-126973-run-8288215085007426999,338101898040651254-2.txt",
    "log": "Shell Game run report\nRandomizer seed: 126973\n…"
  }'

Put the whole file in log, not just its start. It goes in as a JSON string, so its line breaks, quotes and backslashes need escaping; any JSON library does that for you.

A report that is taken gets 201 and its reference:

{"reference":"ABCD-1234"}

Anything else gets an error status and a message written for you, to show as it is:

{"error":"This run log is too large to send (the limit is 1 MB)."}

When a report is refused

The app and the service turn a report away when:

  • the run log's file name doesn't match its mod's run logs (case doesn't matter);
  • the run log isn't UTF-8 plain text;
  • its first line isn't its mod's run-log header, for Shell Game Shell Game run report;
  • the description is empty or over 20,000 characters;
  • the run log is empty or over 1 MB;
  • the mod isn't on the list;
  • one sender has tried more than 5 reports in a minute, sent or not;
  • the service is full for the day, or full overall.

The message says which. Pick another run or shorten the description and send again, or, if the service is busy or full, try again later.

Keep your reference

Every report that gets through has a reference, eight letters and digits such as ABCD-1234, shown by the app or returned by the service. Keep it: it is how your report is found again when you talk about the bug.
